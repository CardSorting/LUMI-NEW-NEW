# Implementation Details & Findings

## What was built (short)

Three independently toggleable capabilities over existing infrastructure — see [how-it-works](../architecture/how-it-works.md). Counts at Phase 11: 455 tests passing in `npm run test:swarm` across Agent Swarm, Legion Host, Tool Handlers, Terminal, and Policy (plus 465 passing in `npm run test:execution` and 32 in webview); core engines, policies and handlers total ~9,500 lines.

## Key findings

1. **Suspension is mostly bookkeeping.** Because the host already had durable per-stream memory and cooperative boundaries, "freeze a hierarchy" reduced to a _protocol_ (requests, acks, checkpoints, a barrier). The hard parts were concurrency and persistence ordering, not the idea.
2. **The store's rules matter more than the feature's logic.** 4 of 10 incidents were persistence semantics (shadow overlays, conflict targets, FK ordering, non-unique reads). See [post-mortems](../postmortems/README.md).
3. **A permissive test double is the most dangerous test asset.** The in-memory `dbPool` mock ignored `agentId`, FK order and key semantics; real-SQLite tests caught defects the mock-based tests could not.
4. **Idempotency must be total.** "Ignore an event equal to the current state" is not idempotency; repeated _different_ events must also be ignored once a state is terminal (PM-009).
5. **Unbounded loops hide in "helpful" automation.** Review, failover and remediation all needed explicit numeric bounds and an escalation exit.
6. **Config has more sources than UIs assume.** settings.json, env, UI, per-task, per-agent, manual invocation; plus a store that pre-fills defaults. Make precedence explicit and visible (UI posts _effective_ values).
7. **Deterministic classification is good enough to start.** Explainable, free and testable; heuristics can be steered with `preferredRoles`/`excludeRoles`.
8. **Interrupted delegation is a first-class failure mode.** See PM-010 / PB-08.
9. **"Commit, then write" strands writes in a private buffer — and same-batch `delete` sorts before `upsert`.** Found late, by probing the real SQLite file with diagnostic queries (`Q1`–`Q8`) rather than reading code; they silently broke barrier release, post-resume child completion, and same-batch reservation deletion ([PM-011](../postmortems/PM-011-completion-state-stranded-in-shadow-overlay.md), [PM-012](../postmortems/PM-012-post-resume-reconcile-and-delete-upsert-ordering.md)). _If you take one lesson: look at the file on disk._
10. **Conductor autonomy requires auto-approval.** Prompting users interactively to approve delegator tools destroys autonomous agent flow. Auto-approving `engage_swarm` preserves sprint velocity while specialist tool sandboxing protects the workspace.
11. **Streaming progress cards make multi-agent systems observable.** Opaque multi-stage execution feels hung. Emitting badge-annotated markdown progress cards (`formatLegionProgressMessage`) keeps users informed across stage transitions and specialist runs.
12. **Snapshot test isolation requires conditional tool suppression.** Dynamically registering new tools alters system prompt token streams and snapshot assertions. Gating tool variants on `!context.isTesting` protects regression test baselines while enabling full capabilities in production.
13. **Failover must distinguish retryable errors from toxic errors.** Indiscriminately retrying exhausted budgets or disallowed tools creates infinite loops. Categorizing `safeToRetry` ensures failover only reroutes recoverable failures.
14. **Streaming transport hygiene & circuit breaking.** Model endpoints yield divergent delta/snapshot contracts (deltas followed by full argument snapshots, or interleaved call IDs). Deduplicating snapshots at the provider level, self-healing duplicate complete JSON roots in `StreamResponseHandler`, and circuit-breaking transport decoding errors with `safeToRetry: false` in `LegionAgentHost` prevents futile specialist failover loops and token waste ([ADR-0014](../adr/ADR-0014-tool-argument-stream-deduplication-and-self-healing-parser.md), [PM-015](../postmortems/PM-015-tool-argument-snapshot-concatenation-and-stream-decoding-loop.md)).
15. **Multi-tier terminal heredoc defense & prompt parity.** Models instructed to perform complex file updates frequently default to terminal heredocs (`cat <<'EOF' > file`, `tee`), which freeze and deadlock non-interactive VS Code shell integration and bypass file tracking and reservation safety. A defense-in-depth architecture across specialist system prompts (`LEGION_CORE_RULES`), pre-execution interception and UI approval suppression (`ExecuteCommandToolHandler`, `UniversalGuard`, `ToolValidator`), shell policy parser (`heredocPolicy`), and terminal process circuit-breakers (`VscodeTerminalProcess`, `VscodeTerminalManager`) completely neutralizes this deadlock vector while providing actionable guidance to use `write_to_file` ([ADR-0015](../adr/ADR-0015-multi-tier-terminal-heredoc-defense-and-prompt-parity.md), [PM-016](../postmortems/PM-016-terminal-heredoc-deadlock-and-prompt-parity.md)).
16. **Multi-tier terminal file read defense & token decoupling.** Directing file reads (`cat`, `head`, `tail`, `more`, `less`) to `read_file` prevents dumping hundreds of lines of code into user terminals. Decoupling token ceilings from multi-turn accumulation stops premature specialist team budget starvation ([ADR-0016](../adr/ADR-0016-terminal-file-read-defense-budget-starvation-and-conductor-prompt-parity.md), [PM-017](../postmortems/PM-017-terminal-file-dump-specialist-starvation-and-conductor-fallback.md)).
17. **Dynamic project knowledge & scoped credential sanitization.** Observations shared across stages accelerate complex workflows. Scoping heuristics by SHA-256 workspace digests and running multi-pattern regex screening against credentials ensures zero secret leakage into prompts or databases ([ADR-0017](../adr/ADR-0017-dynamic-project-knowledge-blackboard-and-credential-sanitization.md)).
18. **Workspace environment integrity & manifest fingerprinting.** Computing deterministic SHA-256 fingerprints across manifest stats (`size`, `mtimeMs`, `ctimeMs`) and invalidating leases reactively upon manifest file edits ensures toolchains reflect disk state without repeated probe overhead ([ADR-0018](../adr/ADR-0018-workspace-environment-integrity-and-manifest-fingerprinting.md)).
19. **Terminal supervision, action fencing & shadow commit retention.** Losing terminal observation is not evidence of process death. Strict `commandOutcome` keeps lost-outcome commands fenced as `unconfirmed`, preventing concurrent build collisions, while `BufferedDbPool` retains uncommitted shadows with `ShadowCommitError` ([ADR-0019](../adr/ADR-0019-terminal-supervision-action-fencing-and-shadow-commit-retention.md), [PM-018](../postmortems/PM-018-unconfirmed-command-outcome-fencing-and-replacement-view-pollution.md)).
20. **Surrogate-safe handoff & settlement verification.** Binary-search byte capping with surrogate-pair protection prevents malformed XML truncation. Two-phase formation reservations eliminate duplicate team races, and `needs_reconciliation` state transitions prevent corrupt or duplicate stage failovers ([ADR-0020](../adr/ADR-0020-legion-handoff-sanitization-two-phase-reservation-and-unsettled-reconciliation.md), [PM-019](../postmortems/PM-019-unpersisted-specialist-settlement-and-formation-dispatch-race.md)).

3. Consider a durable lock if multi-process execution is planned.
4. Optional: LLM re-ranker behind the same manifest contract; telemetry on specialist outcomes to tune keyword weights.
