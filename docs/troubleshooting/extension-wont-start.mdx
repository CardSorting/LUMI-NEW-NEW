## What you might see

If LUMI cannot start, your editor may show an error like:

- `Cannot find module 'better-sqlite3'`
- `better_sqlite3.node ... incompatible architecture (have 'x86_64', need 'arm64')`
- `Activating extension 'CardSorting.lumi' failed`
- A LUMI popup that says the database driver is missing or for the wrong processor architecture

This points to the extension's bundled SQLite driver, not your project code or settings. The driver may be missing, incomplete, or built for a different processor than your editor.

---

## If LUMI opens

<Steps>
  <Step title="Open the health check">
    1. Open the **Command Palette** (`Cmd+Shift+P` on Mac, `Ctrl+Shift+P` on Windows/Linux)
    2. Type **LUMI: Check Installation**
    3. Press Enter
  </Step>
  <Step title="Read the LUMI Health panel">
    A panel named **LUMI Health** opens with a checklist. It names the missing component or architecture mismatch and gives the next step.
  </Step>
  <Step title="Reload">
    Command Palette → **Developer: Reload Window**
  </Step>
</Steps>

---

## Install the matching platform build

If LUMI fails during startup, choose **How to fix** in the error message or **Copy details** to share the diagnostic. Your project files and settings are unaffected.

Apple silicon editors need the **ARM64** build. Intel Mac editors need **x64**. If you see `have 'x86_64', need 'arm64'`, install the `darwin-arm64` VSIX; reinstalling the x64 package will not fix the mismatch.

1. Get the matching `.vsix` from [GitHub Releases](https://github.com/CardSorting/DietCodeMarie/releases). Platform builds include the platform in the filename, such as `lumi-20.0.2-darwin-arm64.vsix`.
2. In the editor, open **Extensions** → **⋯** → **Install from VSIX…** and select that file.
3. Run **LUMI: Check Installation** if LUMI opens, then **Developer: Reload Window**.

---

## Terminal repair (if you have the source repo)

```bash
npm run doctor:fix
```

Then reload your editor window.

---

## If you installed from Open VSX

Some Open VSX clients may install a platform build that does not match the editor's architecture. If you use **Antigravity**, **VSCodium**, or another Open VSX client:

1. Download the matching platform VSIX from [GitHub Releases](https://github.com/CardSorting/DietCodeMarie/releases).
2. Install it using **Install from VSIX…** above.
3. Run **LUMI: Check Installation** to confirm the database driver loads for this editor.

## Command reference

| Who | What to run |
|-----|-------------|
| **Everyone** | Command Palette → **LUMI: Check Installation** |
| **Terminal users** | `npm run doctor` or `npm run doctor:install` |
